 FAZA 2 — M0: AUDIT STATISTIC DE ROBUSTETE (m0/)
================================================================================

Intrebare M0: care sesiuni au un edge REAL, distinct de norocul de cautare?

Metoda (docs/M0_METHOD.md — explicat pe intelesul tuturor):
1. Stationary block bootstrap pe seria de R → P(edge>0) + interval de incredere.
2. Deflated Sharpe / "trial-uri de breakeven" N* → robustete la multiple testing.
3. Consistenta pe 8 fold-uri contigue + trend Spearman → stabilitate in timp.

Pachet construit (read-only, reutilizeaza engine.portfolio.run_portfolio):
- m0/session_runner.py — profil sesiune → params run_portfolio (COPIAT verbatim
  din api/routers/backtest.py). VALIDAT: reproduce baseline-ul 284 trade-uri exact.
- m0/stats.py — bootstrap (vectorizat), PSR/DSR, fold consistency.
- m0/robustness.py — SURSA UNICA DE ADEVAR: evaluate_trades() + classify() +
  to_result_payload(). Folosit de CLI si de API (nu pot diverge).
- m0/audit.py — ruleaza toate 20 sesiuni → data/m0_audit.csv + docs/M0_RESULTS.md.
- m0/selftest.py, m0/validate_runner.py — verificari integritate.

REZULTAT AUDIT (20 sesiuni): 5 KEEP · 3 OBSERVE · 12 DEMOTE.
- De incredere real: S3 (BTC, +0.110R, P=100%, 1176 trades) si S14 (CHFJPY,
  +0.153R, train≈test — cel mai echilibrat).
- KEEP dar sub-esantionate (N mic): S11 (USDCAD, 88t), S17 (AUDCAD, 47t), S18.
- 13/20 sesiuni au tiparul "train negativ / test pozitiv" = edge fragil, un
  singur regim. Concluzie: majoritatea sesiunilor n-au edge dovedit ca atare.

================================================================================
 FAZA 8 — INCIDENT "ZERO TRADES OVERNIGHT" — DIAGNOZA + FIX
================================================================================

Simptom: motorul ruleaza pe M15 dar niciun ordin de aseara pana acum.

Investigatie forensica (ledger data/ai/ledger.db):
- Infrastructura INOCENTA: motor rulat toata noaptea fara gap (4 iteratii/ora),
  MT5 conectat, ZERO erori LLM, 29 consilii convocate (19 breakout-tension!).
- FUNNEL demascator:
  * 29/29 consilii: Analistul Tehnic a spus "neutral" (0 directii date)
  * 29/29 consilii: Risk Manager a dat VETO (100%)
  * 28 decizii, toate WAIT, 0 OPEN, 0 ordine.

ROOT CAUSE (nu bug de infrastructura — politica de decizie care facea
tranzactionarea IMPOSIBILA matematic). Trei defecte compuse in prompturi:
1. Analistul Tehnic nu putea lua pozitie: briefing cu trend M30+D1+W1 care rar
   coincid + prompt "skeptical" → orice dezacord = neutral. (AUDUSD la varful
   range-ului cu M30 bullish — breakout clasic — tot "neutral" ca D1 diferea.)
2. Risk Manager cu veto NELIMITAT + mandat "gaseste motive sa NU tranzactionezi".
   Motivele lui erau analiza tehnica ("RSI neutral", "conflicting trends"), nu risc.
3. Head Trader legat de reguli: "dezacord = WAIT" + "veto = WAIT". Cu portile 1+2
   permanent inchise → P(trade)=0 prin constructie. Paralizie de comitet.
Edge case gasit: veto returnat ca STRING "false" ar fi fost truthy in Python.

FIX (structural + enforced in cod, nu doar prompturi mai bune):
- Analist Tehnic: politica de pozitie — M30+price action = semnal PRIMAR de
  directie; higher-TF conflict scade CONFIDENCE, nu forteaza neutral; pret la
  marginea range-ului cu trend M30 = setup directional; "neutral" doar la chop real.
  Primeste si trigger-ul care a convocat consiliul.
- Risk Manager: veto ENFORCED IN COD — doar cu unul din 6 coduri de risc dur
  (NEWS_IMMINENT, DAILY_STOP, MAX_POSITIONS, EXTREME_VOL, WEEKEND_GAP, BAD_GEOMETRY).
  Veto fara cod valid → IGNORAT ca blocaj, convertit in prudenta (risc redus la
  0.25%). Modelul nu mai poate paraliza desk-ul; codul decide ce e veto.
- Head Trader: regula cantitativa — OPEN in directia analistului la confidence≥55
  daca macro nu semnaleaza risc de eveniment contrar; dubiile scad SIZE, nu decizia;
  ordine STOP = confirmare gratuita (netriggerat = costa nimic).
- Parsing veto robust (_veto_flag): 'false'/'true' string tratate corect.
- Rails de siguranta NESCHIMBATE (geometrie, RR≥1, SL≤5ATR, max 3, -3R, ≤1%, DEMO).

Verificare: 30/30 selftest incl. 4 teste noi de veto. Testul decisiv — acelasi
consiliu live care veta un setup bullish curat ieri, acum da OPEN_LONG conf=75%
cu SL/TP valide, risc 0.5%. Motor repornit pe fix. report.py arata acum un FUNNEL
(consilii → veto onorate vs. degradate → actiuni → plasate).
